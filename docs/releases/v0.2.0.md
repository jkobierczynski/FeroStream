FeroStream runs a Linux program on a remote host and shows its windows on Windows as if they were local: each remote window is a real Win32 window with its own taskbar button, moved and resized like any other.

```
ferostream.exe me@build-box gimp
```

This is the first published release. It is the same code FeroSSH has run for Session > Remote apps since v1.3.0 (protocol 7), plus the build changes below, so its agents and FeroSSH's are interchangeable.

## Downloads

| File | What it is |
| --- | --- |
| `ferostream.exe` | The Windows client (x64). Native Win32, no toolkit, no installer. Not code signed yet. |
| `ferostream-agent` | The Linux agent for x86-64 hosts: one static binary, no root, no daemon. |
| `ferostream-agent-aarch64` | The same for 64-bit ARM hosts (Raspberry Pi OS, Graviton). |
| `SHA256SUMS.txt` | Their SHA-256 sums. |

Keep the three programs in one folder. The client copies the right agent to a host that lacks it (or has another version) over the same SSH connection, picked by the host's `uname -m`. Each file and the sums carry a build provenance attestation: `gh attestation verify ferostream.exe -R jkobierczynski/FeroStream`.

The host needs Xvfb (`sudo apt install xvfb`; Fedora: `xorg-x11-server-Xvfb`).

## What it does

- **Native windows.** Titles and icons on the taskbar, text sized for your screen's scaling, the program's pointer shapes, dialogs above their window, menus and tooltips without a frame, size limits, and minimise, maximise and full screen from either side.
- **Your normal OpenSSH.** The client starts the agent through `ssh.exe`, so keys, `~/.ssh/config`, jump hosts and host-key checks work as they already do. Passwords and host-key questions appear in a small dialog. Nothing listens on the network.
- **Small pictures.** The agent sends only pixels that changed, scrolls as copies of pixels the client already has, and packs each tile the way that suits it (one colour, a palette, or filtered rows), then LZ4 or Deflate, picked by the link speed (`--packing auto`, `fast` or `strong`). Scrolling 60 lines in xterm takes about 25 KB.
- **Clipboard.** Copied text goes both ways, up to 1 MiB. `--clipboard to-host`, `from-host` or `off` limits it; mouse selections from the host stay there unless you add `--share-selection`.
- **Keyboard.** Typing goes through your Windows keyboard layout, dead keys and AltGr included, so the host needs no matching layout.
- **Dropped connections.** The program keeps running on the host; its windows stay, marked "(reconnecting…)", and fill again when the client is back. `--attach` brings back a session you closed, and `ferostream-agent --list` and `--stop ID` manage them on the host.
- **Embeddable.** `ferostream-client` is also a library that runs sessions inside another program's message loop, with the decoder in a separate sandboxed process. FeroSSH uses it this way.

## Security

- Every frame is length-checked before anything is allocated, and the frame decoder, the client's decoder, tile packing, the window properties the agent reads and the clipboard pieces are fuzzed.
- Unlike X11 forwarding, a remote program never sees your Windows keystrokes or screen, only the input you send to its own windows.
- The Xvfb display is reachable only through a Unix socket and a random cookie; session sockets live in `/tmp/ferostream-<uid>/`, a directory only you can enter.
- On the host, the agent locks itself down once your program runs: no new privileges, not dumpable, a seccomp filter (no `execve`, no sockets but Unix ones, no ptrace, namespaces, BPF, io_uring or `TIOCSTI`) and, on Linux 5.13 and later, Landlock. `ferostream-agent --check-sandbox` shows what a host enforces.
- A copied agent is checked by size and CRC before it replaces the old one, and is executable by you only. `--remove-agent` deletes it when its program ends.

## Building and releases

- **The agents build on Windows without WSL.** `.cargo/config.toml` now links both agents with `rust-lld`, which comes with Rust, so `cargo build --release --locked -p ferostream-agent --target x86_64-unknown-linux-musl` (and `aarch64-unknown-linux-musl`) works the same on Windows, Linux and macOS. Before, Windows stopped with ``linker `cc` not found``. `rust-toolchain.toml` now also installs the ARM64 target. CI builds both agents on Windows to keep it that way.
- **CI uploads the ARM64 agent.** The `ferostream-agents` artifact has both agents, named as the client looks for them, and the `ferostream-windows-x64` package now holds `ferostream.exe` and both agents (it had only the x86-64 one).
- **Release workflow.** Pushing a `v*.*.*` tag checks it against `Cargo.toml` and these notes, runs every CI job, and publishes the files above with attestations.
- The README explains how to build the agents, including for the FeroStream commit a FeroSSH build pins.

Not yet: screens with different scaling, QUIC, code signing for `ferostream.exe`.
